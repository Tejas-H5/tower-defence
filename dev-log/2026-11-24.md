# 2026-11-24 - graphics

We can now run 100,000 enemies, 50 towers and very fast bullets + priority queue thing from last dev log at 120FPS! 
Or at least, that is what I thought. 
Even though every subsystem showed 120FPS, the game itself was lagging pretty bad. 
I guess the one thing I forgot to measure was the render time!
Now that there are so many things we're rendering with raylib's immediate-mode API, it is lagging.

The key is to switch to instanced rendering.
We are actually already well positioned to do this!
It's just that it's not quite in the format that Raylib expects.
I'll have to create a default material, and then a custom shader so that instancing can work.
After a load of faffing around, I was not able to get instancing working at all. 
I was able to get it working in ThreeJS but I don't think I'll be able to do it for Raylib.
Does my game really need 100k enemies? Probably not. 

Besides, what I found is that my physics subsystems weren't all that great - 
the slow render speed allowed my physics simulation to remain in an earlier stage where not much
was colliding - once I stopped rendering stuff to see what would happen, the FPS values plummeted to
their real values - about 40-50fps. 
Decent, but it's not fast enough to warrant instancing - the physics are too big of a bottleneck
for me to start implementing faster graphics, at least for now.

For now I've just reverted my code back to the immediate-mode stuff.
We will pretend this never happened.
