2026-11-19 - Odin iterators - a common pitfal, and how to get out

So far, I've got a spatial query acceleration structure that lets me accelerate line x rectangle queries. 
It's interface is something like this:

```odin
physics_update :: proc(game: ^Game_state) {
    // Somewhere in there
    {
        bullet_ray := Line{bullet.position_prev, bullet._position}
        it := spatial_grid_line_iterator(&game.spatial_grid, bullet_ray)
        for slot in spatial_grid_line_iterate(&it) {
            enemy_pool := cast(^Item_Pool(Entity))slot.pool
            if enemy_pool == &game.enemies {
                // This slot's handle must be for an enemy

                j := slot.handle - 1
                other_rect := get_rect(&state.enemies, j)
                res := line_intersects_rect(bullet_ray, other_rect)
                if res.num_hits > 0 {
                    set_entity_position(game, pool, i, res.hits[0].pos)
                }
            }
        }
    }
}
```

Ok after copying that over and simplifying it, it's still kinda ass. 
I'll fix that later and make a dev log out of it. 
But anyway, the point is that the iterator is supposed to work like this:

- for every point along the ray that intersects with a grid:
    - make a rectangle centered on `point.pos` with a width and height of `grid.max_entity_radius`, `rect`
    - for each grid square that `rect` touches:
        - if we haven't already `visited` this square:
            - yield this slot

Seems simple enough. 
But odin doesn't have `yield` style iterators!
It turns out that there is a subtle flaw in how I've composed my iterators in general that
was making things quite difficult.
The line iterator is a bit complicated, so for demonstration purposes, I'll use
my rectangle iteratore as an example. 
This iterator is supposed to iterate all grid coordinates between `it.from` and `it.to`, which are both `[2]i32`s:

```odin
rect_iterator :: proc(it: ^Spatial_Grid_Rect_Iterator) -> (^Spatial_Grid_Slot, bool) {
    res, ok := point_iterate(it.point_iterator)
    for !ok { // We need to keepp stepping our point till we find a single item.
        it.pos.x += 1
        if it.pos.x > it.pos.to.x {
            it.pos.x = 0
            it.pos.y += 1
        }

        if it.pos.y > it.pos.to.y {
            return nil, false
        }

        it.point_iterator = point_iterator(it.spatial_grid, it.pos)
        res, ok = point_iterate(it.point_iterator)
    }
    return res, ok
}
```

It seems pretty natural, given that the way we yield a result out of our iterator is by using `point_iterate`.
But there is a subtle duplication in our logic - now there are two places in our code responsible for stepping
the line iterator.
This is subtle, but I ended up using this pattern for the line iterator as well.
It works fine untill I want to do something like "if we haven't already `visited` this square":

```odin
rect_iterator :: proc(it: ^Spatial_Grid_Rect_Iterator) -> (^Spatial_Grid_Slot, bool) {
    res, ok := point_iterate(it.point_iterator)
    if res.item.visited {
        ok = false
    }
    for !ok { // We need to keepp stepping our point till we find a single item.
        it.pos.x += 1
        if it.pos.x > it.pos.to.x {
            it.pos.x = 0
            it.pos.y += 1
        }

        if it.pos.y > it.pos.to.y {
            return nil, false
        }

        it.point_iterator = point_iterator(it.spatial_grid, it.pos)
        res, ok = point_iterate(it.point_iterator)
        if res.item.visited {
            ok = false
        }
    }
    return res, ok
}
```

This `res.item.visited` check needs to be in two places now!
And I don't want to move it into `point_iterate` - only the `rect_iterator`
cares about deduplicating grid slots (well really in my case, it's `line_iterator`, 
but I feel this is simpler to get the point accross).

There is an alternate formuation for iteration, and you'll know it by going back to basics:

```c
for (
    int i = 0;  // initialize
    i < n;      // check
    i++         // increment
) {
}
```

I wonder if I can rewrite all my iterators in odin to be like this - 
rather than using `res, ok = rect_iterate(it)`, I would be directly accessing
fields on `it` to get the current iteration state, and then calling `rect_iterate` without
reading it's return values to iterate the thing:

```odin
example :: proc() {
    for it := rect_iterator(g); it.from.x <= it.to.x || it.from.y <= it.to.y; rect_iterate(&it) {
        // My code here.
        log(it.slot)
    }
}
```

`it.from.x <= it.to.x || it.from.y <= it.to.y` could be put into a `rect_iterated` function xDD.
I won't bother.
