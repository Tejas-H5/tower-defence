# 2026-11-11 - Lots of entities

I've done a bit of prototyping so far, and I store all my entities in a linear array of fat structs.
My current game has a bunch of enemies that spawn around the base and attack it. 
I place down guns that shoot bullets at the closest enemy. 

If I place down 100 guns, they'll all execute code like this:

```odin
for gun in game {
    if gun.type != .Gun {continue}
    closest_enemy := nil
    for enemy in game {
        if enemy.type != .Enemy {continue}
        if enemy in range and is closer than closest_enemy {
            closest_enemy = enemy
        }
    }
}
```

This code is tremendously slow. 
When the guns start shooting, the game also slows down because I need to iterate more things.
The dillema presents me with these options:

- Break up the entities list into many smaller lists, do something like ECS
    - The game is now much harder to work on
- Use lookup strucutres to somehow iterate through less things
    - Hard to code and takes time (but I've always wanted to code one of these so thats nice I guess)
- Use some other heuristic for what the guns will attack
    - Acknowledge that the AI in this game has an upper bound to what it's capable of

I actually think it's easiest to do the heuristic approach.
Instead of computing the closest enemy for every gun, we can loop the enemies once and compute a list of
which ones are closest to the base. 
Then the guns can pick from this list.
Seems like a pain to program as well.
Maybe lookup structure is the way to go??
Moving different entity types to their own arrays is also a good idea - 
that way shooting a bunch of bullets won't lag all the traversals.
Dont need to go full ECS.

NOTE: This problem only exists if we set the shoot cooldown to 0.01 or some very slow number such
that the gun fires basically every frame. 
If it shoots less frequently, it's not much of a problem it seems.
I do want to support fast fire rates and lots of weapons.

I might have to code this thing again from scratch maybe?

They have a way to 'target' another entity by supplying an entity handle. 
Some options:

- Make a new target type that specifies which entity map the array is really in
- Get rid of this idea of a 'target type' and make all my entities re-resolve such targets every frame.
    - Put SOA on everything
    - Order would no longer matter, so everything can be in normal arrays, use unordered_remove.
    - Coordinating entities that spawn at the same time can remember their ids when they spawn, and check
        if `id == entities[id].id` to know if the reference is still valid. (NOTE: only works if we clear the last element id to -1 when we swap remove)

Right now it's only the bullets that are the problem, so solely moving them to a seperate container should fix things.
